BEAVR 双臂遥操 ​

通过 BeaVR 遥操栈 接管 Onero A1 双臂：头显推手部关键点，PC 侧实时反解成末端位姿并经 onero-sdk 伺服下发，同时支持左右手各自的二指夹爪。本文使用的代码是它的分支仓库 Onero_A1_beavr-bot，额外包含下文描述的 Start 启动 gate 与夹爪手势加固。

本页是面向集成与操作人员的完整部署流程，按顺序执行，每步都有可验证的结果。

真机操作提示

进入 Start 才启用。 头显 App 建立连接后就会推关键点，但臂保持静止；只有在 App 里进入 Start，PC 侧才进入遥操并做一次复位，之后手在视野内的移动会 1:1 传到机械臂。

启动前清空机械臂下方空间，确认无人进入运动范围。停止时：先捏合左手拇指与无名指暂停，再关闭遥操作程序，最后断电。

适用条件 ​

项目内容
适用型号Onero A1L（左臂）、Onero A1R（右臂）
通信方式SocketCAN 直连，1 Mbps（USB-CAN / slcan）
配套软件BeaVR 遥操栈 + onero-sdk[full] + 头显 App
适用对象首次部署 A1 双臂 VR 遥操的集成与操作人员

目标 ​

完成 BeaVR 遥操栈、onero-sdk 和头显通信依赖的安装，并通过自检确认环境可以启动双臂遥操。

接线与 CAN 接口（一次性） ​

接线 ​

  1. 断电状态接好：左右臂 24V、两根 USB-CAN、末端夹爪（如有）。
  2. 上电。
  3. 确认设备节点：
bash
ls -l /dev/ttyACM*
1

ttyACM0/ttyACM1 的编号由插入顺序决定，每次开机可能互换。 不得假设编号 0 对应右臂。确认方法：先仅连接一只臂，记录新增设备；再连接第二只臂，记录新增设备。

任一端为裸法兰（无夹爪）时，onero_config.py 的 with_gripper 需关闭，否则重力前馈过量。

绑定 can0 / can1 ​

bash
# 右臂
sudo slcand -o -c -s8 /dev/ttyACM0 can0
sudo ip link set can0 up
sudo ip link set can0 txqueuelen 1000

# 左臂
sudo slcand -o -c -s8 /dev/ttyACM1 can1
sudo ip link set can1 up
sudo ip link set can1 txqueuelen 1000
1

-s8 表示 1 Mbps。slcand 是前台进程，各自占用一个终端（或 nohup ... &）。

txqueuelen 1000 为必需配置。 默认队列长度仅为 10，双臂以 30 Hz 伺服时可能在数毫秒内溢出并丢失反馈帧，进而触发单臂通信超时急停；典型表现为“一只臂停止运动，另一只保持正常”。

接口名与默认值一致时无需设环境变量：

变量默认含义
ONERO_CAN_CHANNELcan0右臂
ONERO_LEFT_CAN_CHANNELcan1左臂

双臂模式下两者必须不同（同名会直接报错）。

主机地址与头显连接 ​

主机地址 ​

所有组件通过该地址互连，头显 App 也必须连接同一地址。该地址必须是运行本程序的本机局域网 IP：

bash
export BEAVR_HOST_ADDRESS=$(hostname -I | awk '{print $1}')
echo $BEAVR_HOST_ADDRESS        # 必须是本机地址，不能是 127.0.0.1
1
2

三个必须知道的点：

  1. 换机器、换网络后必须重设。 代码里的默认值是出厂的验证机地址，DHCP 重新分配后就会失效。
  2. 地址填写错误时通常不会直接报错，表现为“一切启动正常但机械臂不运动”：teleop reset 始终无法获取数据。此时应优先检查该地址配置。
  3. 环境变量只在当前 shell 有效，每开一个终端都要重新 export。

启动前自检 ​

关节限位 ​

bash
python3 -m beavr.scripts.check_onero_joint_limits --laterality=bimanual
1

只读，不会让电机动作。期望两只臂都输出：

reset(): OK -- within limits, teleop can start
1

两种失败：

  • reset(): FAILED -- IK feedback exceeds URDF limits：某关节超出限位。表中带 <-- OUT 的行对应超限关节，将该臂调整至中位后重新测试。最常见原因是腕部末端自转关节被手动旋转至极限。
  • no joint feedback received：臂未上电/未使能，读数不可信。上电后重测。

启动通过的判据 ​

每个 operator 依次出现：

****** onero_<side>_operator: RESETTING TELEOP ******
TELEOP RESET COMPLETE
[onero_<side>_operator] calibration re-derived from the measured baselines ...
1
2
3

两臂均不应自行转动或抽动。点 Start 后终端是否打印 RESETTING TELEOP，是判断「输入是否通」的唯一硬判据：

  • 打印了 → 链路正常
  • 一直不打印 → App 没推流（IP 不符 / 未点 Start / 防火墙），与臂无关
  • 打印了但持续输出 SVD did not converge → App 发送的关键点全部为零，见 常见问题

复位时手的位置决定整场精度

出现 TELEOP RESET COMPLETE 时，系统会将手部位姿与机械臂实测位姿共同记录为映射基准。复位期间系统持续等待手部帧（实测等待 25~58 秒），操作手进入视野后的第一帧将被用作基准。

复位时将手放置在实际操作姿势：胸前、与肩同高、距身体 30~40 cm，并保持不动，直到出现 TELEOP RESET COMPLETE。手部下垂或偏转会导致基准偏移，进而使后续所有目标整体偏移，表现为 IK 持续不收敛或机械臂基本不运动。

目标 ​

点击头显 App 的 Start 后完成双臂复位，使手部关键点经过实时反解转为末端目标，并由 onero-sdk 持续下发到左右机械臂和夹爪。

模式切换手势（仅左手） ​

来源：ARCLab-MIT/BeaVR-app 的 GestureDetectorXR.cs，阈值均为 0.02 m。

手势（左手）作用边框
拇指 + 食指捏合切到 relative 模式，正常遥操绿
拇指 + 中指捏合切到 absolute 模式蓝
拇指 + 无名指捏合暂停红

三条要点：

  1. 仅左手生效。 右手执行相同动作不会切换模式，这是常见误区。夹爪不受此限制，左右手分别控制对应侧夹爪。
  2. 绿框 = 已连上 PC 且处于 relative 遥操模式，两者同时成立。
  3. 手势走头显手部追踪，与手柄无关，手柄没电不影响；但手必须在视野内、系统「手部追踪」已开启。

首次动作与方向确认 ​

手平移 2~3 cm，目视确认方向：

手动作期望世界方向
向右-Y
向前+X
向上+Z

跟随有滞后：手移动 5 cm，臂大致跟到 3~4 cm 是正常的（kp=50 偏低，属预期，不是故障）。方向确认后再放大到 5~10 cm。

首次验证只向上移动：三个轴的方向符号是对称的，确认 Z 向上即可推断 Y 与 X。

夹爪（左右手各管一侧） ​

Onero 自带型号，与臂共用同一条 CAN 总线（命令 0x08 / 反馈 0x18），两态控制。左手控制左夹爪，右手控制右夹爪，互不影响：

操作效果
该侧手拇指 + 小指距离 < 45 mm该侧夹紧
距离 > 65 mm该侧张开
  • 必须使用小指，不得使用食指。 拇指与食指/中指/无名指的捏合用于模式切换；使用小指可避免同时触发模式切换。小指尖为第 25 号关键点，App 本身未使用该关键点。
  • 单臂模式下只有对应那一侧的手有效。
  • 45~65 mm 是回差区，防止阈值附近抖动；进入回差区不改变状态。
  • 闭合阈值设为 45 mm 而非更小值：手掌背向头显且小指部分遮挡时，头显估算的两指尖距离可能大于实际距离（实测捏合时约 40 mm）；阈值过小可能导致捏合后夹爪未闭合。
  • 退抖：距离取最近 3 帧的中值，且张开需连续 3 帧、闭合需连续 2 帧满足条件才切换。单帧追踪跳变不会误触发，代价是动作晚约 70~130 ms。
  • 手部未被追踪时保持当前状态，不会自动松开。
  • 夹爪失败（未接、未上电、CAN 冲突）只打 WARNING，不中断遥操。
  • 未安装夹爪时，把 onero_config.py 的 gripper_enabled 设为 False。

安全与停止 ​

点击 Start 后启用 ​

在 App 中点击 Start 是唯一的启用入口。OneroOperator 启动后处于 STOP 状态，只有收到 App 的 continue 信号才进入遥操作：

  • App 的 Pause 通道每帧发 High（继续）/ Low（暂停）；Start 按钮回调 ActivateStreaming() 把 ShouldContinueArmTeleop 置真后才开始发 High。
  • detector 只放行这两个状态值，其余一律丢弃：KEEPALIVE 心跳（每 5 s）与 DIAGNOSTIC_TEST_Pause_* 探针（socket 建立后立即发一次）。转发后 High → pause（=继续）、Low → resume（=暂停），operator 只把 pause 当启动码。
  • 启动 gate 关闭期间 operator 完全跳过继承的 retargeting：不发布指令、不复位、也不打印 RESETTING TELEOP。复位只在点 Start 后的第一帧发生一次，此时手应已在准备位置。
环境变量默认含义
ONERO_REQUIRE_START1置 0 回到「推流即启用」
ONERO_START_COMMANDpause反相接法时改成 resume
ONERO_START_FALLBACK0默认关闭。置 1 允许 Start 通道失效时降级放行
ONERO_START_FALLBACK_S8静默多久判定通道失效（秒）

ONERO_START_FALLBACK 默认关闭，以确保“Start 之前绝不动作”。仅在确认 pause 端口映射存在问题（ss -tnp | grep :8100 未检测到连接，但关键点流正常）时临时设置为 1；此时 pause 通道静默 8 s 且关键点仍持续发送有效帧，operator 将降级放行并输出一条 WARNING。

因此：

  • 启动前将手放置在头显视野之外；待 teleop.py 启动并确认双臂静止后，点击 Start，再将手放入视野。
  • Start 之前机械臂不会跟随手部运动（也不会复位）；Start 之后，只要手部位于视野内，所有手部移动都会 1:1 传递到机械臂，包括非操作性手势。

已知限制 ​

项说明
home 键未接通，按下无反应；home_on_start=False，启动时不返回停靠位
pause 键已接通。App 的 High/Low 经 detector 反转后分别发布为 pause/resume，keepalive 心跳被单列。左手拇指+无名指捏合（红框）置 STOP，臂保持最后指令；捏食指（绿框）恢复。恢复会走一次 STOP→CONT 的复位，需重新摆好手位并等 20~60 s
分辨率档位键已接通：App 在 button 通道发 Low/High → detector 转 ARM_LOW/HIGH_RESOLUTION，operator 据此缩放臂分辨率
跟踪精度kp=50 标量，静止静差约 10 mm；per-joint 增益在 SDK 内部有值但不可达
频率默认 VR_FREQ=30；改 100 需改源码常量并保留 txqueuelen 1000
向下运动停靠位未针对具体台面验证；首次使用前自行确认台面高度与下方障碍
双臂长时间运行CANable2 使用 slcan（串口），吞吐有限，双臂并发接近上限，可能导致单臂丢帧急停。彻底解决需刷写原生 gs_usb 固件
末端边界手伸到工作空间边缘时 IK 可能短暂不收敛，保持上一个目标 0.1~1.2 秒。属安全行为，收回即可恢复

复位后 IK 持续不收敛、机械臂基本不运动复位时手部位置不正确，导致映射基准偏移。重新执行复位，将手放置在胸前自然姿势并保持至出现 TELEOP RESET COMPLETE
