本页内容

多路点搬运 ​

本案例让 Onero A1 依次经过四个关节路点，对比逐点停顿和轨迹融合两种执行方式，用于说明巡检、码垛和搬运任务的基本路点组织方法。

真机操作提示

示例支持 MuJoCo 和 CAN 真机。仿真路点没有验证实际安装环境中的工具、负载、障碍物和线缆，不能直接用于真机。程序结束时会失能机械臂；失能前必须可靠支撑机械臂及负载。

演示目标 ​

示例依次完成以下流程：

  1. 使用 movej() 逐点执行四个关节目标，每到一个路点都停稳；
  2. 使用 TrajectoryPlanner 重新组织相同四个路点；
  3. 为前三个路点设置轨迹融合，在途经点连续过渡；
  4. 最后一个路点取消融合并返回零位；
  5. 默认在 MuJoCo 中执行，添加 --real 后连接真机。

该示例不包含夹爪控制、物料接触或碰撞规划，“搬运”只表示任务路点的组织方式。

操作阶段 ​

顺序阶段操作含义
1创建后端默认创建 MuJoCo；--real 时连接 A1R 和 can0
2逐点移动使用 movej() 执行四个路点，每点停稳
3构建规划器以 200 Hz 添加相同的四个路点
4轨迹融合前三点连续过渡，最终点停止
5结束处理失能、关闭通信，并在仿真模式下关闭窗口

真机运行 ​

首次真机运行前应：

  1. 检查每个目标是否在关节限位内，并确认左右臂的关节方向差异；
  2. 检查路点之间的完整轨迹、奇异位形和碰撞风险，而不仅是终点；
  3. 配置真实 TCP、工具与工件总质量和合成重心；
  4. 先取消轨迹融合并以较低速度逐点验证；
  5. 逐点路径确认安全后，再从较小的融合参数开始验证连续轨迹。
bash
python examples/19_multi_waypoint.py --real
1

真机模式不会打开 MuJoCo 窗口，终端阶段与仿真模式相同。不要仅凭“轨迹完成”判断任务安全，还应现场确认每个路点、过渡轨迹和最终状态。

结果判断 ​

运行成功应同时满足：

  • 逐点阶段按顺序到达四个路点，每个路点有明确停顿；
  • 融合阶段在前三个路点连续过渡，并在最终零位停稳；
  • 终端输出“轨迹完成”，没有限位、通信或执行异常；
  • 真机路径与现场预检一致，工具、负载和线缆未接近障碍物；
  • 程序结束时机械臂得到可靠支撑并正常失能。

仿真结果只能验证接口、路点组织和理想模型下的轨迹，不能证明真机定位精度、负载能力或碰撞安全。

中断与安全状态 ​

程序在正常结束或异常退出时都会调用 disable()，随后关闭通信；仿真模式还会关闭 MuJoCo 窗口。close() 和关闭仿真窗口都不等于停止真机运动。

如果真机出现非预期方向、接近碰撞、振荡或通信异常，应使用现场适用的紧急停止措施。排除原因前不得直接重新运行或通过增大融合参数绕过问题。
