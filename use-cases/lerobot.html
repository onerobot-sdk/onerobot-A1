LeRobot 遥操作与数据采集 ​

代码不在本文档仓库里，在独立项目 Onero_A1_Lerobot（默认分支 main）

真机操作提示

启动即使能从臂；退出（q 或 Ctrl+C）会失能，退出前托住手臂。

安装与部署 ​

使用 Ubuntu 24.04 + Python 3.12+（仅遥操作支持 Python 3.10+）：

bash
git clone https://github.com/switchbot-rd/Onero_A1_Lerobot.git
cd Onero_A1_Lerobot
sudo bash scripts/setup.sh
1
2
3
  • 仅进行遥操作而不录制数据时可加 --base（不安装 PyTorch / LeRobot / 录制依赖）。
  • 脚本最后会做一次不碰 CAN 的自检（URDF、动力学、视频编解码；x86 另含 MuJoCo 模型）。

目标 ​

完成 LeRobot 项目及其依赖安装，并通过不使能电机的自检确认环境可以进入后续遥操作流程。

接线与固定接口（一次性） ​

四条手臂 → CAN 接口 ​

物理臂型号配置里的位置接口
左主臂（遥操手柄侧）A1Lteleop.arms.leftcan1
右主臂（遥操手柄侧）A1Rteleop.arms.rightcan2
左从臂（被跟随侧）A1Lrobot.arms.leftcan3
右从臂（被跟随侧）A1Rrobot.arms.rightcan4

左右由 model（A1L/A1R）和 mounting（humanoid_left/humanoid_right）决定；can1–can4 只是绑定名字，必须按上表绑定，否则跟随方向会错。

每条臂独占一个适配器和一个接口，速率 1 Mbit/s。

如何确认物理臂角色：通过末端部件识别——主臂末端为按压手柄，从臂末端为两指夹爪；臂身标有 A1L/A1R，不得根据接口编号推断。

接线错误的典型现象：启动遥操作后，连接至 can3/can4 的机械臂发生非预期运动（主臂被误作为从臂使能），同时日志反复报告 Gripper fault: protocol=onero code=12 state=12（手柄电机被误作为夹爪驱动）。出现上述任一现象时，应立即按 Ctrl+C 停止程序，并依据上表重新绑定接口。

把 USB-CAN 适配器绑成 can1–can4 ​

查看适配器的稳定串口名称（名称由适配器序列号决定，与插入的 USB 端口无关）：

bash
ls -l /dev/serial/by-id/
1

根据表格完成绑定（将四个 <...> 替换为上一条命令输出的实际名称，并保持与上表顺序一致）：

bash
sudo bash scripts/setup_can.sh can1 /dev/serial/by-id/<左主臂适配器>-if00
sudo bash scripts/setup_can.sh can2 /dev/serial/by-id/<右主臂适配器>-if00
sudo bash scripts/setup_can.sh can3 /dev/serial/by-id/<左从臂适配器>-if00
sudo bash scripts/setup_can.sh can4 /dev/serial/by-id/<右从臂适配器>-if00
1
2
3
4
  • 重新插拔后先执行 sudo bash scripts/cleanup_can.sh，再重新绑定：残留的 slcand 仍指向已失效的 ttyACMx，会导致对应的 canN 消失（ip -brief link show type can 的输出中缺少相应接口）。
  • 重启或重新插拔后接口会消失，重跑上面四条命令即可；脚本不设开机自启。

校验接线（只读，不使能任何电机） ​

bash
python scripts/can_precheck.py                      # 按内置约定查 can1/can2/can3/can4
python scripts/can_precheck.py --watch 10 can1 can2 # 手动转动目标臂，确认对应通道读数变化
timeout 5 candump can3                              # 仅接收不发送，确认总线上是否存在数据帧
1
2
3

判据：DISABLED 表示未使能的正常状态；出现 NO REPLY / ERROR(...) 或通道无法打开时，应先排查线序、供电和 --tx-queue，再继续后续操作。

更换适配器或调换 CAN 线后，必须使用 --watch 重新确认接口与物理臂的对应关系，再依据上表重新绑定。

遥操作 ​

全量 / 增量：所有配置默认增量（teleop.reference: "relative"）——从臂停在启动位置，只复现主臂的位移，启动时不会追位。需要全量（把主臂当前位姿整体交给从臂）时，在命令后加 --reference absolute，不用改 JSON。

全量模式要求启动时从臂与主臂每个关节都在 startup_max_delta_rad（3.0 rad）以内，且启动瞬间从臂会移动到主臂姿态。

单臂：右主臂 → 左从臂 ​

仅连接所需的两条臂（can2 右主臂 / can3 左从臂），其余两条保持当前状态：

bash
onero-a1-lerobot-teleoperate --session-config configs/sdk_right_leader_left_follow.json
1

单臂：左主臂 → 右从臂 ​

两种映射二选一（can1 左主臂 / can4 右从臂，其余两条保持当前状态）：

bash
# 逐关节映射（joint：每个关节按 joint_signs 的符号传给从臂）
onero-a1-lerobot-teleoperate --session-config configs/sdk_left_leader_right_follow.json

# 镜像映射（mirror：主臂增量取反；加 --reference absolute 时是绝对镜像）
onero-a1-lerobot-teleoperate --session-config configs/sdk_single_mirror.json
1
2
3
4
5

单臂：同侧（左主臂 → 左从臂 / 右主臂 → 右从臂） ​

同侧跟随将主臂关节角按原值（joint_signs 全 +1，joint 模式）传递给同侧从臂，can1→can3（左）、can2→can4（右），其余两条臂保持当前状态：

bash
# 左主臂（can1）→ 左从臂（can3）
onero-a1-lerobot-teleoperate --session-config configs/sdk_left_leader_left_follow.json

# 右主臂（can2）→ 右从臂（can4）
onero-a1-lerobot-teleoperate --session-config configs/sdk_right_leader_right_follow.json
1
2
3
4
5

左右不能共用一个文件：CLI 未提供覆盖 channel 的参数，而 teleop.arms / robot.arms 的键（left/right）、model、mounting 与 joint_signs 均随侧别变化。两份配置除这些字段外完全相同，切换侧别时需修改 4 处：robot.arms.<side>.channel、teleop.arms.<side>.channel，以及两处 arms 的键名。

双臂（默认） ​

目标 ​

按会话配置启动双臂主从跟随，并观察主臂动作被映射到对应从臂；同一流程也可切换到单臂配置验证单侧跟随。

bash
onero-a1-lerobot-teleoperate --session-config configs/sdk_dual_joint_follow.json
1

运行中可用参数 ​

bash
# 每秒打印主臂、映射后的目标、从臂实测与误差（不录制）
onero-a1-lerobot-teleoperate --session-config configs/sdk_dual_joint_follow.json --diagnostics-interval 1

# 限制会话时长为 60 秒（到时自动结束）
onero-a1-lerobot-teleoperate --session-config configs/sdk_dual_joint_follow.json --duration 60

# 无硬件：mock 臂，不打开 CAN 和相机
onero-a1-lerobot-teleoperate --session-config configs/sdk_dual_joint_follow.json --simulate --duration 5

# 无硬件：MuJoCo 窗口（x86 环境）
onero-a1-lerobot-teleoperate --session-config configs/sdk_dual_joint_follow.json --simulate mujoco --viewer

无硬件：MuJoCo 仿真 ​

bash
onero-a1-lerobot-teleoperate --session-config configs/sdk_dual_joint_follow.json --simulate mujoco --viewer
1

同一份会话配置切换至 MuJoCo 后端后，接口、映射与交互命令均不变，仅将下发目标发送至仿真模型并打开窗口。MuJoCo 3.12.0 仅安装于 x86_64 主机（见 安装与部署），arm64 机器人本体只能使用 --simulate 的 mock 臂。连接真机前可先使用该模式验证跟随响应，无需 CAN 和相机。

目标 ​

在 MuJoCo 中复现双臂跟随和交互命令，验证会话配置、关节映射与控制流程，无需连接 CAN 或相机。

数据采集 ​

目标 ​

按会话配置启动双臂数据采集，生成包含相机和关节观测的本地 episode，并在退出时完成保存。

bash
onero-a1-lerobot-record \
  --session-config configs/sdk_dual_joint_follow_cameras.json \
  --repo-id local/a1_cameras --task "双臂操作采集" \
  --root ./datasets/local/a1_cameras
1
2
3
4

启动后立即开始录制，Ctrl+C 停止并保存；也可以通过 --duration 60 限制会话时长。

命令行为
r开始录制；再次输入结束当前 episode 并保存（保存完成后才能开始下一段）
p暂停/恢复跟随；暂停会先结束当前录制
q 或 Ctrl+C结束会话，失能手臂，等待录制收尾
  • --duration 表示会话时长，不是录制时长。
  • 保存成功的标志：Post-record conversion complete 和 Episode writer finished ... status=saved。生成期间不要关闭终端，也不要开始下一段。

数据集可视化 ​

目标 ​

读取已保存的 episode，在本地可视化查看相机画面与关节轨迹，不打开 CAN，也不使能电机。

bash
bash scripts/viz.sh --repo-id local/a1_cameras --root ./datasets/local --episode 0
1
  • 仅读取数据集目录，不打开 CAN、不使能电机；采集完成后可逐帧查看相机画面与关节轨迹。
  • --root 指向包含 <repo-id> 子目录的根目录（这里即 ./datasets/local），脚本会把它设成 HF_LEROBOT_HOME；等价的手写命令是 HF_LEROBOT_HOME=./datasets/local lerobot-dataset-viz --repo-id local/a1_cameras --episode-index 0 --mode local。
  • --mode distant --grpc-port 9876 起 gRPC 服务给远端 rerun 连；--save 1 --output-dir ./output 导出 .rrd 而不弹窗。
  • lerobot-dataset-viz（rerun）随 lerobot[dataset-viz] 只在 x86_64 安装，arm64 的机器人本体上没有这个命令，需在开发机上执行。

动作回放 ​

目标 ​

读取指定 episode，先将从臂平滑对齐到首帧，再按数据集帧率回放动作；使用 --simulate 时仅驱动 mock 从臂。

bash
onero-a1-replay-episode \
  --session-config configs/sdk_dual_joint_follow_cameras.json \
  --repo-id local/a1_cameras --root ./datasets/local/a1_cameras --episode 0
1
2
3
  • 回放前至少用 3 秒平滑对齐到第 0 帧；--align-duration 5 可延长对齐时间，--no-align 可跳过对齐（仍保留首帧距离保护）。
  • 对齐过程不执行避障规划，应先清空运动路径；回放过程不打开相机。
  • --episode N 选片段，--fps 覆盖数据集帧率，--simulate 用 mock 从臂。

策略训练 ​

目标 ​

使用本地数据集训练 ACT 策略并保存检查点，为后续 rollout 提供可加载的策略模型。

bash
lerobot-train \
  --dataset.repo_id=local/a1_cameras --dataset.root=./datasets/local/a1_cameras \
  --dataset.return_uint8=true \
  --policy.type=act --policy.device=cpu \
  --policy.repo_id=local/act_a1 --policy.push_to_hub=false \
  --output_dir=outputs/train/a1_act --job_name=a1_act \
  --steps=5000 --batch_size=8 --num_workers=4 --save_freq=1000 --wandb.enable=false

真机部署 ​

目标 ​

加载已训练策略和匹配的相机输入，在 Onero A1 真机上执行有限时长的策略 rollout；演示模型只用于展示流程，不代表实际抓取效果。

bash
onero-a1-lerobot-rollout \
  --config_path=configs/native_dual_joint_follow_rollout.json \
  --strategy.type=base \
  --policy.path=outputs/train/a1_act/checkpoints/last/pretrained_model \
  --task="双臂操作采集" --duration=10
1
2
3
4
5
  • 该命令会先获取两路相机的首帧，因此必须已连接相机；仅验证策略链路时使用下面的无硬件运行方式。
  • rollout 使用的相机和分辨率必须与训练数据一致，否则策略输入不匹配。
  • base 策略不支持键盘热键：通过 --duration 到时结束或按 Ctrl+C 结束；两种方式都会先平滑返回启动姿态再失能，连续按两次 Ctrl+C 可跳过回位。
  • 启动前将从臂调整至接近录制起始姿态；偏差过大时会触发首帧保护并拒绝启动。
  • 加 --display_data=true 可查看实时画面（rerun）。

常见故障 ​

现象处理
canN: ... No such device / 接口消失重启或重插后接口不会自动恢复，重跑上面的四条绑定命令
Hardware fault on joint N: code=0x0 (Cannot verify motor state before enable)使能前读取该关节状态时丢失一帧（SDK 仅检查一次，超时为 50 ms）；启动程序会自动重试 4 次。若仍反复出现：执行 python scripts/can_precheck.py canN -n 30 查看该通道丢帧率，并检查对应机械臂的 CAN 线束（尤其是腕部弯折处）与终端电阻
启动后 can3/can4 的机械臂发生非预期运动，或夹爪报告 Gripper fault ... code=12 state=12主从臂接线错误（can3/can4 连接的是主臂）：依据上方接线表重新绑定，主臂应连接至 can1/can2
拖动机械臂时 canN 读数不变、其他通道读数变化接口与物理臂的对应关系错误：执行 python scripts/can_precheck.py --watch 10 can1 can2 can3 can4 重新确认后绑定
启动数秒后出现 Tracking error ... on joint N 或 SDK state is stale先确认是否添加了 --reference absolute（默认 relative 不会启动追位）；再将从臂悬空重试，并检查 dmesg / ip -s link show canN，排除该通道反馈中断
回放报告 Cannot align left: first replay target JN=... outside [...] rad数据集首帧超出该关节限位（录制时姿态越界），对齐前检查会直接拒绝。加 --no-align 跳过对齐（SDK 会将目标限制在关节限位内），或选择其他数据片段
