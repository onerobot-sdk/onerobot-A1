本页内容

夹爪与触觉传感器 ​

本案例把一只 Onero 夹爪直接接到 USB-CAN 适配器上，不连接机械臂、不创建 Arm，用于单独验证夹爪通信、开合控制和选配触觉传感器读取。

真机操作提示

夹爪闭合时会产生夹持力，可能夹伤手指或损坏工件。运行前必须清空夹持区域、可靠固定夹爪和线缆，并确保供电可随时切断。disable() 会撤销夹持力；在夹持工件或有人接近时，不得随意失能。

演示目标 ​

示例依次验证：

  1. 只通过 CanBus 和 OneroGripper 建立夹爪通信，不依赖机械臂；
  2. refresh() 在未使能时读取反馈，不改变夹爪目标；
  3. 连续 3 次全开 → 全闭，结束后回到全开；目标按 50 Hz 分步下发，动作连续平滑；
  4. 触觉模块在线状态查询；
  5. 读取传感器 1 和传感器 2 的合力点，以及传感器 1 的 10 个测点原始值；
  6. 连续读取合力点，观察手指接触时原始值的变化。

硬件连接 ​

项目要求
CAN 适配器只用一条 USB-CAN 通道连接夹爪，本页示例使用 can0
波特率1 Mbit/s
终端电阻总线两端按现场规范配置 120 Ω 终端电阻
供电按夹爪铭牌要求供电，上电前检查线序
设备 IDSDK 按出厂默认 ESC_ID=0x008、MST_ID=0x018 通信

蓝色 USB 线连接主机与 USB-CAN 适配器，适配器引出 CAN 信号线；夹爪另一侧的红黑线为独立供电。照片只用于核对整体连接关系，具体线序以实物定义为准。

接线前重点核对：

  • 供电规格以夹爪铭牌和随箱说明为准，上电前核对正负极，不要凭经验假设。
  • 供电正负和 CAN_H/CAN_L 不能仅凭线色判断；适配器侧可参考机械臂安装中的红 CAN_H、黑 CAN_L 约定，夹爪侧以随箱说明为准。
  • 适配器不隔离时需确认夹爪与适配器共地；使用隔离型 USB-CAN 时按适配器说明接线。
  • 总线两端按现场规范配置 120 Ω 终端电阻，上电前检查接头是否插紧，运动中避免拉拽 CAN 和供电线缆。

CAN 速率固定为 1 Mbit/s。原生 SocketCAN 适配器：

bash
sudo ip link set can0 down 2>/dev/null || true
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
ip -details link show can0

串口转 CAN 适配器（slcand，设备节点按实际连接修改）：

bash
sudo slcand -o -c -s8 /dev/ttyACM0 can0
sudo ip link set can0 up

-s8 表示 1 Mbit/s。持续高频下发时可以同时提高发送队列：

bash
sudo ip link set can0 txqueuelen 1000
1

完整接线、驱动与排障见连接真机。配置完成后可先观察原始反馈：

bash
candump can0
1

执行 refresh()、enable() 或触觉读取时，适配器应能看到来自 0x018 的反馈帧。若设备 ID 已被修改，SDK 不会自动探测，需先按 Onero A1 自研夹爪 CAN 协议恢复默认 ID。

不要同时运行其他控制程序

同一 CAN 通道只能有一个程序发送夹爪目标。运行示例前应关闭 Debug UI、Arm 程序和其他夹爪控制脚本，避免目标帧互相覆盖。

操作阶段 ​

独立夹爪控制 ​

顺序接口操作含义
1CanBus()打开 can0
2OneroGripper(bus=..., model=...)选择左右端点标定，绑定通信
3refresh()未使能时读取反馈
4enable()使能电机并读取反馈
5set_position()按 50 Hz 步进，用约 1.5 s 从当前开度平滑走到目标
6refresh()轮询到位，或判断位置已停滞在机械端点
7disable()撤销夹持力
8shutdown()关闭 CAN 接口

触觉传感器 ​

顺序接口操作含义
1OneroGripper(..., with_tactile=True)创建触觉对象，不发送额外帧
2get_online_status()查询两个触觉口是否在线
3recalibrate()可选，执行重标定
4read_resultant()读取单个传感器的合力点
5read_points()读取连续测点
6read_resultant() 循环观察接触时的原始值变化
7shutdown()关闭 CAN 接口

需要理解两点：

  1. set_position() 返回的同步反馈通常反映发送控制帧之前的状态，不能据此判断新目标已经执行完成。示例用 refresh() 轮询，根据位置、速度和状态判断动作进展。
  2. enable() 后状态中的 motion_state 应为 1；出现 8..14 时表示过压、过流、过温、通信超时或编码器异常等故障，应立即停止并检查硬件。

停止与释放资源分两步：disable() 只撤销电机使能和夹持力；shutdown() 关闭由 owns_bus=True 打开的 CAN 接口。shutdown() 不会让夹爪失能。

raw_mask 为设备返回的原始位掩码，bit0 对应传感器 1，bit1 对应传感器 2。with_tactile=True 只表示“已配置选配模块”，不代表传感器当前在线，应以 get_online_status() 为准。

重标定 ​

重标定用于让传感器重新建立“无负载”基线，可以理解为触摸力的零点标定，不是量程或灵敏度标定。SDK 读取设备返回的原始值（Fz = fz_raw × 0.1 N），不会在软件中额外减去零点。

执行前需要满足以下“无接触”状态：

  • 两个感应面完全裸露，没有手指、工件、夹具、线缆或胶带接触；
  • 夹爪未抓取任何物体，两指之间没有夹持物；
  • 夹爪静止，没有开合动作，也没有外部碰撞或明显振动；
  • 两个触觉传感器在线，安装姿态与正常使用时一致；
  • 建议在刚上电或环境温度明显变化后先静置片刻再标定。

结果判断 ​

独立夹爪控制：

  • CanBus() 能打开 can0，refresh() 在未使能时也能收到反馈；
  • enable() 不超时，反馈 motion_state=1，position 在 0.0..1.0 内；
  • 三次开合动作连续完成，速度均匀平滑，没有明显卡顿；每次动作约 1.5 秒；
  • 全闭时反馈可能停在 0.06 左右而不是 0.000。这是该夹爪的机械端点与标定差异，示例会打印“已到机械端点”，不应视为未闭合；
  • 最后的反馈范围应接近 0.06 .. 1.00，且开合方向与实物一致；
  • 失能后夹爪不再保持夹持力，shutdown() 后 CAN 接口被释放。

触觉传感器：

  • get_online_status() 返回的掩码与已安装的传感器数量一致，两个都装时为 3；
  • read_points() 返回 10 个连续编号的测点，没有超时或序号错误；
  • 空载时读取稳定；用手指轻触传感器 1 的感应面，Fz_raw 明显变化，离开后回落；
  • 对传感器 2 重复轻触，表现一致；
  • 重标定（如启用）时两个传感器均返回 0x01。

原始值变化只用于验证链路和方向，不能据此换算成经过标定的力值或精度指标。

生命周期与安全 ​

操作作用不会做什么
enable()使能夹爪电机不会让夹爪自动闭合到某个开度
set_position(0.0)目标全闭不会等待动作完成
disable()撤销使能和夹持力不会关闭 CAN 接口
shutdown()关闭 owns_bus=True 打开的接口不会让已使能的夹爪失能
  • 夹爪与机械臂共用同一 CAN 通道时，应由 Arm 统一管理 transport，不要同时创建独立的 CanBus。
  • 本页示例直接以电机级 MIT 帧控制夹爪。不要在另一个进程中同时发送产品级 GRIP_CONTROL 目标，两种目标会互相覆盖。
  • 详细帧格式、状态码和参数读写约束见 Onero A1 自研夹爪 CAN 协议。
  • 夹爪 API 说明见 TCP、负载与末端工具。
