碰撞检测 ​

本案例在规划运动中启用多策略碰撞检测，通过力矩变化率和关节功率异常识别接触，并在触发后记录碰撞事件、停止运动和失能机械臂。默认使用 MuJoCo 注入力矩冲击；确认无误后，才可在符合示例安装条件的真机上验证。

真机操作提示

碰撞检测是接触后的软件启发式检测，不是几何避障，也不是经过安全认证的保护停止。真机测试只能使用固定、柔软的泡棉障碍物；不得用人体、手持物或刚性物体主动碰撞机械臂。测试前必须固定并支撑机械臂，清空无关人员和物品，确保现场紧急停止及断电措施可用。

演示目标 ​

示例依次完成以下流程：

  1. 创建 A1R，按右肩垂直安装配置使能机械臂并设置中等刚度；
  2. 启用 Impact 和 Energy 两个检测通道，同时配置自动停止与事件回调；
  3. 让指定关节在限位内运动；仿真模式约 1.6 秒后自动注入力矩冲击；
  4. 触发时输出检测通道、关节、强度和停止位置；
  5. 未触发时完成整段运动并报告结果；
  6. 结束时失能机械臂并关闭通信。

Impact 和 Energy 通道不依赖精确动力学模型或已知负载。阈值仍会受到安装方式、刚度、速度、工具、负载和传动状态影响，必须针对实际设备验证。

安装与准备 ​

进入 onero-sdk 仓库并安装仿真依赖：

bash
cd ~/workspace/onero-sdk
source .venv/bin/activate
pip install -e ".[sim]"

真机运行前还需要完成 CAN 接口配置与连接检查，并逐项确认：

  • 设备是 A1R，安装方向与示例的 humanoid_right 一致；
  • 基座、线缆和柔软泡棉障碍物均可靠固定，失能后机械臂仍有可靠支撑；
  • 目标关节、运动方向和完整扫掠范围已经在无障碍条件下检查；
  • 已先用默认仿真确认检测与停止流程；
  • 操作者知道真机模式没有运动前确认提示，运行命令后会直接使能并开始运动。

安装方式、型号或测试姿态不一致时，不得直接运行真机命令；应先修改并重新验证示例配置。

参数说明 ​

参数默认值说明
--real关闭添加后连接真机；不添加时运行 MuJoCo
--channelcan0真机 SocketCAN 通道
--joint2运动关节，范围 J1～J7
--amplitude1.0关节运动幅度，单位 rad；程序会按剩余行程选择正向或反向
--impact-threshold80Impact 通道阈值；越低越敏感，也越容易误报
--energy-threshold25Energy 通道阈值；越低越敏感，也越容易误报

示例还固定使用 min_velocity=0.05、warmup_frames=100 和 CollisionResponse.BOTH。预热期间不会触发；BOTH 表示触发时既执行回调，也通过 SDK 紧急停止路径立即失能电机。示例阈值只是演示起点，不是安全额定值。

真机验证 ​

先在无障碍条件下运行一次，确认运动方向、完整路径和默认阈值不会误报：

bash
python examples/25_collision_detection.py --real --channel can0
1

无碰撞时应完成运动并输出：

text
运动完成，未检测到碰撞。
演示结束，机械臂已自动失能。

随后固定柔软泡棉障碍物，在保持人员远离运动区域的条件下再次运行。接触后应在到达目标前停止，并输出触发通道、关节、强度、阈值和停止位置。输出数值取决于实际接触，不应与视频逐值比较。

若泡棉接触未触发，只能小幅降低 --impact-threshold，每次调整后都必须先做无障碍运动检查误报。不得通过换用更硬障碍物、增大速度或反复撞击来寻找阈值。

演示视频 ​

视频先展示一次无障碍运动，再展示 Impact 通道检测到 J2 接触并停止。视频中的接触方式仅用于记录已有测试结果。

结果判断 ​

运行成功应同时满足：

  • 无障碍运行完成，且没有误报；
  • 仿真冲击或真机泡棉接触发生后，目标运动提前结束；
  • 回调中的通道、关节和强度与停止信息一致；
  • last_collision 能返回本次碰撞事件及停止位置；
  • 程序最终输出机械臂已经失能。

若无障碍运动误报，应检查阈值、安装方向、刚度、工具、负载、线缆拖拽和反馈噪声。若明显接触未触发，应先检查关节速度是否低于 min_velocity、检测通道是否覆盖当前运动接口以及参数是否生效，不能直接把碰撞检测用于人员防护。

覆盖范围与安全边界 ​

自动检测覆盖 movej()、movel()、、movec()、speedj() 和 speedl() 产生的规划运动；不覆盖 servoj()、servop() 或主动接触的 force_mode()。回调在控制循环线程中执行，只能做快速记录或通知，不能执行阻塞操作。

碰撞检测不包含桌面、墙体、工具或另一条机械臂的几何模型，无法在接触前规划无碰撞路径。需要几何避障时，应使用 MoveIt 2 运动控制 或应用层规划器。

中断与安全状态 ​

检测触发且响应包含停止时，SDK 进入紧急停止路径并立即失能电机；这与 stop() 的减速停止不同。无碰撞的正常路径会显式调用 disable()。真机运行发生其他异常时，示例也会调用 emergency_stop()；无论哪种失能路径，机械臂都会撤销保持力矩，必须继续提供可靠支撑。

关闭通信或仿真窗口不等于停止运动或失能。重新运行前必须确认机械臂已经停止、障碍物已经移除，并查明误报、漏报或异常停止原因。

标定入口 ​

动力学和运动学入口使用与标定说明对应的 SDK 提交 8a834b9f6fb18207f108bdae8aa5c36b8f34c204，分别是 MuJoCo 双阶段辨识和离线合成数据演示。请使用该提交的完整 SDK；当前 master 的同名脚本已改为真机交互流程。

类型目的示例入口
软件零位建立可复现的用户关节零位软件零位说明
动力学标定辨识惯性和关节摩擦参数动力学标定示例（文档对应版本）
运动学标定修正关节原点并改善模型一致性运动学标定示例（文档对应版本）
手眼标定求解相机与法兰或基座之间的变换手眼标定示例

标定文件不得在不同机械臂、序列号、安装方向或工具配置之间直接复用。

结果判断 ​

力控运行成功应同时满足：

  • 三组场景按顺序完成，接触力方向与所选坐标系一致；
  • 进入和退出接触过程平稳，没有振荡、冲击或持续位置漂移；
  • 每个场景结束后退出力控，最后返回关节零位；
  • 终端没有通信、限位或动力学异常。

标定结果还应按类型判断：动力学标定的 residual_rms 是力矩模型拟合残差，不是末端定位精度；运动学标定的 residual_mm 只描述采集触点的模型收敛程度，必须使用独立检测点验证；手眼标定还需要相机内参、同步采集和未参与求解的数据验证。

所有标定结果都应与型号、序列号、左右侧、安装方向、工具、固件和 SDK 版本一起保存。

中断与安全状态 ​

若接触力方向错误、工具滑动、接触面松动或机械臂出现振荡，应立即使用现场适用的安全措施。不能通过增大目标力、延长持续时间或提高刚度来绕过异常。

程序正常结束或发生异常时会调用 disable()；这会撤销保持力矩，不是普通停止。异常发生在力控循环内时，不应仅依赖终端退出判断设备状态，必须现场确认机械臂已经停止并得到可靠支撑。
