常见问题 ​

Q1：close() 会让机械臂失能吗？ ​

默认不会。close() 释放通信和后台资源，但不会主动撤销电机保持力矩；close(disable=True) 才会先失能再关闭。这样设计是为了避免承受重力或负载的机械臂在通信关闭时突然下落。

只想结束程序但继续保持当前位置时使用 close()；明确需要撤销保持力矩且机械臂已可靠支撑时，才使用 disable() 或 close(disable=True)。close()、stop()、disable() 和紧急停止不能互相替代。

Q2：movej() 和 movel() 如何选择？ ​

movej() 规划关节空间点到点运动，通常适合快速换位、回到准备姿态或已知关节目标；TCP 在运动过程中不保证沿直线。movel() 对 TCP 的完整直线路径逐点求解 IK，适合插装、涂胶和直线接近等路径敏感任务。

如果只要求到达另一个姿态，优先使用 movej()；如果工具作用点必须沿直线移动，再使用 movel()。两种接口都不会自动完成现场碰撞检查。

Q3：为什么 movel() 的方向与预期不一致？ ​

movel() 的目标由 frame 解释。基座坐标系不一定等同于现场理解的前、左、上；设置 TCP 后，工具坐标轴还会随当前末端姿态旋转。

优先检查：

  • frame 是 base、world、tool 还是自定义坐标系；
  • mounting、world_frame 和 base_position 是否符合实际安装；
  • 左右臂型号是否正确，是否误用了另一侧的关节方向或安装参数；
  • set_tcp() 中的位置和旋转是否来自实际工具测量；
  • 使用 frame="tool" 时，输入是否按相对位移理解，而不是绝对坐标。

排查时先调用 get_pose(frame=...) 记录当前位姿，在 MuJoCo 中发送 2～5 cm 的单轴小幅目标，并保持当前旋转矩阵。不要仅靠反复修改正负号试探真机方向。

Q4： 为什么会出现 IK did not converge？ ​

如果出现 IK did not converge，优先检查以下项目：

  • 是否从全零伸直等奇异位形开始；先用 movej() 到非奇异准备姿态；
  • 绝对 TCP 目标是否过远或超出工作空间；先从当前位置做 2～5 cm 小幅运动；
  • 是否遗漏目标姿态；仅验证平移时应读取并保持当前 TCP 姿态；
  • TCP 偏移、安装方向和左右臂型号是否与真机一致；
  • 路径中间点是否经过关节极限或奇异区，而不只是最终目标是否可达。

单纯增加 IK 迭代次数不能解决不可达目标、奇异起点或错误姿态约束。

Q5：为什么使能后机械臂会下沉或抖动？ ​

常见原因是重力补偿使用了错误的机械模型或动力学参数，也可能是 CAN 反馈不稳定、机械结构松动或关节已经接近限位。不要通过盲目提高增益掩盖配置问题。

优先检查：

  • model 和 mounting 是否与左右臂及实际安装方向一致；
  • 工具与工件的总质量、合成重心和 with_gripper 配置是否正确；
  • 电机反馈、CAN 错误计数和通信周期是否稳定；
  • 机械臂底座、末端工具、线缆和关节连接是否可靠固定；
  • 当前姿态是否接近关节极限、奇异区或承载能力边界。

出现持续下沉、快速振荡或异常噪声时，应立即使用现场适用的安全措施并支撑机械臂，不要重复使能测试。排除安装、负载和通信问题后，再进行小幅、低速验证。

Q6：为什么仿真可以运行，真机却不能运行？ ​

MuJoCo 主要验证模型、参数格式和规划路径，不会自动复现现场的供电、CAN 接线、固件、零位偏差、真实工具、线缆和临时障碍物。因此仿真成功不能直接证明真机条件已经满足。

按以下顺序检查：

  1. 机械臂型号、安装方向、TCP、负载和真机目标是否与仿真一致；
  2. 供电、USB-CAN 设备、CAN 通道、波特率和终端电阻是否正常；
  3. 关节反馈是否连续有效，当前姿态是否在模型限位内；
  4. 真机工作空间内是否存在仿真没有建模的工具、线缆或障碍物；
  5. 先读取状态，再执行分离、小幅、低速目标，不要直接运行完整任务。

CAN 接口不存在、无法收到电机状态或错误计数持续增加时，按 CAN 排查处理，不要反复使能或发送运动。

Q7：为什么会出现 Pinocchio 报错？ ​

若电脑之前安装ROS执行过 source /opt/ros/humble/setup.bash 后，ROS 会把自己的 Python 包和原生库路径加入 PYTHONPATH、LD_LIBRARY_PATH。随后激活 .venv 只会切换 Python 可执行文件，不会清除这些路径，结果可能是虚拟环境的 NumPy、Pink 与 ROS 自带的 Pinocchio 二进制被混合加载。

常见现象包括：

text
A module that was compiled using NumPy 1.x cannot be run in NumPy 2.x
AttributeError: _ARRAY_API not found
ImportError: ... undefined symbol ...
Segmentation fault
1
2
3
4

只运行普通 SDK 示例时，可临时隔离 ROS 路径：

bash
unset PYTHONPATH
1

长期使用时，不要在 ~/.bashrc 中无条件加载 ROS，也不要通过降级 NumPy 掩盖路径冲突。
