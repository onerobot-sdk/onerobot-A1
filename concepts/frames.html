坐标系 ​

坐标系的核心问题是“目标相对于谁表达”。同一个 [x, y, z] 数值，在 base、world 和 tool 下可能对应完全不同的实际方向；编写笛卡尔运动前，应先明确当前默认坐标系，并在跨模块代码中尽量显式传入 frame。

常用坐标系 ​

  • base：URDF 中 base_link 的固有坐标系，固定在机械臂基座上。
  • world：统一世界坐标系，约定 X 向前、Y 向左、Z 向上。
  • tool：当前 TCP 的局部坐标系；用于相对增量运动。
frame原点与方向常见用途
baseURDF base_link 的原点与轴向单臂运动学和安装调试
world统一的现场坐标双臂、场景和 MoveIt 规划
tool当前 TCP 的局部坐标沿工具轴线做相对位移

坐标变换链为：

text
world → base → flange → TCP
1

base 坐标系 ​

base 不是“前、左、上”的另一种写法，而是固定在 Onero A1 基座上的局部坐标系。它的定义来自 onero-sdk 当前版本的 A1L/A1R URDF；机械臂怎样安装、关节怎样转动，都不会改变 base 相对于机械臂本体的原点和轴向。

原点和三轴 ​

A1L 与 A1R 的 URDF 在基座处使用相同的坐标关系：

项目URDF 定义物理含义
原点base_link 的建模原点位于基座安装端面中心
关节 1 原点相对 base_link 为 [0, 0, 0.0315] m，姿态不旋转从 base 原点沿 +Z 前进 31.5 mm
+Z关节 1 的转轴为 [0, 0, 1]沿基座轴线，从安装端面指向机械臂；关节 1 的正方向按右手定则绕此轴旋转
+X关节 1 零位时，Link1 与 base_link 的轴向对齐位于安装端面内；外壳特征只能用于辅助识别
+Y与 +X、+Z 构成右手坐标系+Y = +Z × +X

安装后与 world 的方向关系 ​

mounting 只规定 base 如何旋转到 world，不会重新定义 base。

下表以 world +X = 前、world +Y = 左、world +Z = 上 表示当前 onero-sdk 中各预设的精确轴向：

mountingbase +X 指向base +Y 指向base +Z 指向
uprightworld +X（前）world +Y（左）world +Z（上）
a1_verticalworld +Z（上）world +X（前）world +Y（左）
humanoid_leftworld +Z（上）world +X（前）world +Y（左肩外侧）
humanoid_rightworld +Z（上）world -X（后）world -Y（右肩外侧）
side_mount_leftworld +X（前）world -Z（下）world +Y（左）
side_mount_rightworld +X（前）world +Z（上）world -Y（右）
ceilingworld +X（前）world -Y（右）world -Z（下）

位置变换可写成：

text
p_world = R_world_base × p_base + base_position
1

其中 mounting 决定旋转矩阵 R_world_base，base_position 只决定 base 原点在 world 中的位置。world_frame=True 只是把笛卡尔接口的默认表达坐标系切换为 world；仍可显式传入 frame="base" 读取或发送基座坐标。

真机方向验证

不要仅凭外壳朝向或反复修改正负号来试探真机。先在 MuJoCo 中显示坐标轴并验证 mounting，再在无障碍物、低速条件下执行小幅运动；确保随时可以停止运动或触发紧急停止。

python
arm = Arm(
    "A1R",
    channel="can0",
    mounting="humanoid_right",
    world_frame=True,
    base_position=[0.0, -0.15, 0.8],
)

mounting 决定方向，base_position 决定基座原点在世界坐标系中的位置。错误配置可能导致运动方向或重力补偿方向不正确。

world_frame=True 适合需要把左右臂放进同一场景的程序；单臂调试时也可以先使用默认 base，但必须在代码和文档中明确坐标系，避免把基座轴误写成现场的前、左、上。

工具坐标系 ​

调用 set_tcp() 后，笛卡尔接口以工具中心点为参考：

python
arm.set_tcp(position=[0.0, 0.0, 0.15])
arm.movel([0.0, 0.0, 0.03, 0.0, 0.0, 0.0], frame="tool")
1
2

frame="tool" 表示相对当前 TCP 的增量，不是绝对目标位姿。

选择坐标系的检查顺序 ​

  1. 确认 A1L/A1R 和 mounting 与实际安装一致。
  2. 确认 world_frame 是否开启，以及 base_position 是否正确。
  3. 设置 TCP 后重新读取 get_pose()，确认返回的是法兰还是 TCP 位姿。
  4. 对 frame="tool" 的小幅位移先在仿真中验证方向，再迁移到真机。

坐标系问题通常表现为“数值看起来正确，但机械臂方向相反或工具偏移不对”。此时先检查坐标变换，不要直接修改目标数值抵消错误。

目标表达方式 ​

除选择坐标系外，还需要区分“绝对目标”和“相对增量”。它们使用相同的数值格式时尤其容易混淆：

表达方式含义适合场景首次验证方法
frame="base" 或 frame="world" 下的目标目标相对固定参考系表达到达场景中的已知位置在仿真中确认轴向和目标位置
frame="tool" 下的增量位移相对当前 TCP 局部轴表达沿夹爪、吸盘、探针轴线进给从几毫米/厘米的小位移开始
关节数组直接给出 7 个关节角预设姿态、回零、避开奇异位形检查每个关节限位和中间路径

设置 TCP 后，get_pose() 与笛卡尔运动的参考点都会发生变化；它不会改变关节数组本身，也不会自动更新负载。工具变更时，应把 TCP、负载和坐标系检查视为一组操作，而不是只修改其中一个参数。
