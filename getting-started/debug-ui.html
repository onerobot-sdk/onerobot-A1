Debug UI ​

SDK 内置浏览器调试界面，可用于观察状态和执行受控调试。建议先完成连接真机中的 CAN 检查，再启动界面。

启动 ​

Debug UI 适合做状态查看、单步调试和仿真联调；它不是任务编排器，也不是安全控制器。复杂轨迹、持续伺服和真机首次运动仍应优先使用可审查的 Python 脚本。

bash
# 单右臂真机
python -m onero_sdk.debugui --arm right --channel can0

# 双臂仿真
python -m onero_sdk.debugui --arm both --sim

启动后访问 http://localhost:8090。

启动方式 ​

模式命令特点用途
单臂真机指定 --arm right 和 --channel can0查看指定通道的状态并进行受控调试
双臂仿真指定 --arm both --sim不连接 CAN，验证界面和双臂状态展示

浏览器与启动进程必须在同一台机器上时，直接访问 localhost；如果通过远程桌面或端口转发访问，应额外确认端口暴露范围和网络权限。

使用注意 ​

  1. 仿真模式先确认页面能加载、模型状态能更新。
  2. 真机模式先确认机械臂已固定、CAN 通信正常，并清空运动范围。
  3. 任何运动按钮执行前，先确认当前姿态、速度和工具配置。
  4. 页面失联时不要继续点击运动命令，回到终端执行受控停止或按现场流程断电。

WARNING

Debug UI 不是安全控制器。浏览器断开、页面关闭或网络异常不能替代断电。操作真机时应持续观察机械臂与周边环境。

推荐使用边界 ​

操作适合在 Debug UI 中完成仍应使用脚本或现场措施
查看关节状态和连接情况是记录长期诊断日志
复核小幅单步目标是，且先在仿真验证复杂任务编排和连续轨迹
验证工具配置可查看状态和小幅响应TCP/负载标定与工艺验证
中止常规运动可请求停止人员或设备危险时的急停、断电

每次用界面发送真机目标前，先记录当前姿态和按钮对应的参数。若结果不符合预期，不要连续点击相同按钮试错；应先停止运动，再回到坐标系、TCP、负载与末端工具和 CAN 状态逐项检查。
