安装与仿真 ​

建议先在虚拟环境中完成仿真验证，再连接真机。

推荐流程是：安装基础包 → 安装所需可选依赖 → 运行仿真 → 确认版本和模型 → 配置 CAN → 进行低速真机验证。不同功能对应不同 extra，不需要一次安装所有依赖。

安装 SDK ​

SDK 已发布到 PyPI。建议在虚拟环境中按所需功能安装：

bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install "onero-sdk[sim]"

第一个仿真程序 ​

python
from onero_sdk import Arm
from onero_sdk.mujoco_backend import MujocoBackend

backend = MujocoBackend(model_name="A1R")
arm = Arm("A1R", backend=backend)

try:
    arm.enable()
    arm.movej([0.0, -0.5, 0.3, -1.0, 0.0, 0.5, 0.0], duration=2.0)
    arm.home(duration=2.0)
finally:
    arm.disable()
    backend.close()

完整源码：仿真基础运动案例。

仿真程序的最小生命周期为：创建 MujocoBackend → 创建 Arm → enable() → 发送运动 → 读取状态或回零 → 关闭后端。仿真后端不打开 CAN，因此可以先验证模型、关节目标和基本 API，再迁移到真机。

可选依赖 ​

安装项用途
.[ik]逆运动学和笛卡尔运动
.[dynamics]重力补偿、示教和力控
.[sim]MuJoCo 仿真
.[trajectory]Ruckig、TOPP-RA 轨迹规划
.[python-can]python-can 与 SLCAN
.[full]安装全部可选功能

依赖选择建议 ​

需求推荐安装项说明
只使用关节运动和状态读取基础包不需要 IK 或 MuJoCo
使用 movel()、movec() 或 TCP.[ik]提供笛卡尔运动所需的逆运动学依赖
使用示教、重力补偿或力控.[dynamics]需要动力学相关依赖
在本机验证模型.[sim]安装 MuJoCo 仿真后端
组合完整开发环境.[full]依赖较多，安装时间和磁盘占用更高

安装完成后，建议先运行一个不连接 CAN 的仿真程序，再进入连接真机。

安装后验证 ​

安装成功至少应覆盖“导入、版本、所需依赖和最小仿真”四项。它们分别定位 Python 环境、发布版本、extra 安装和模型后端问题：

检查命令或动作成功判据
导入 SDKpython -c "import onero_sdk; print('ok')"输出 ok，无导入异常
确认版本python -c "import onero_sdk; print(onero_sdk.__version__)"版本与当前任务基准一致或已明确差异
确认仿真依赖导入 MujocoBackend不报告缺少 MuJoCo 或模型资源
最小仿真运行本页示例能创建模型、发送关节目标并退出

若导入成功但仿真失败，不要立即安装全部 extra。应先确认当前解释器、报错中缺少的可选依赖以及主机架构，再只补齐该功能需要的安装项。
