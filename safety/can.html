CAN 排查 ​

CAN 排查应按“接口状态 → 总线统计 → 只读帧 → SDK 反馈 → 设备配置”的顺序进行。排查阶段尽量只读，不要用未知数据帧反复尝试控制设备。

基础检查 ​

bash
ip -details link show can0
ip -statistics link show can0
candump can0
1
2
3

建议先记录排查前后的统计信息：

bash
ip -statistics link show can0
ip -details link show can0
1
2

重点关注 RX/TX 是否增长、errors 是否持续增加，以及接口是否因为错误进入停止状态。

常见现象 ​

现象检查项
找不到 can0USB 设备、驱动、接口命名
接口为 DOWN执行 sudo ip link set can0 up
无反馈帧电源、终端电阻、线序、波特率
大量 error frame接地、布线、终端电阻、总线负载
个别关节无响应关节供电、CAN ID、连接器

不要在不了解协议和设备状态时发送任意 CAN 帧。错误帧可能改变设备状态或触发运动。

排查流程 ​

  1. 确认 USB-CAN 设备节点和驱动已加载。
  2. 确认 CAN 比特率为 1 Mbps，接口状态为 UP。
  3. 使用 candump 做短时间只读检查，确认总线上有反馈帧。
  4. 用正确的型号和通道创建 Arm，读取一次状态。
  5. 只有状态稳定、机械臂固定且工作空间清空后，才进行低速运动验证。

建议保存的诊断记录 ​

CAN 故障常常与供电、接线或启动顺序有关，单次“恢复正常”不足以说明根因已消失。每次问题出现时，建议在不影响安全的前提下保存：

记录用途
ip -details link show can0接口状态、比特率和错误状态
ip -statistics link show can0RX/TX 计数和错误计数是否增长
短时间 candump can0 输出总线是否有预期反馈帧
SDK 异常和时间戳关联应用层超时与总线状态
型号、通道、适配器和接线变更区分配置问题与设备问题

排查期间不要把重启接口、拔插设备和发送控制帧混在同一轮测试中。一次只改变一个条件，并在改变后先做只读验证，才能判断问题是否真正得到缓解。
