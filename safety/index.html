状态、异常与停止 ​

安全处理的优先级是：先让机械臂停止继续运动，再确认机械支撑和供电状态，最后分析异常原因。不要在机械臂仍可能运动时先关闭通信或删除错误日志。

读取状态 ​

python
state = arm.state
print(state.joints)
print(state.velocities)
print(state.torques)
1
2
3
4

状态读取可用于确认目标是否被接受、运动是否仍在进行以及异常前后的反馈变化。记录状态时建议同时保存时间戳、模型、通道和当前工具/负载配置，便于复现问题。

异常处理 ​

以下内容按当前 onero-sdk 源码整理。异常名称、字段和交付方式都是 API 合约的一部分；不要根据异常类的名称推断实际行为。

真机安全

捕获异常不等于机械臂已经安全停止。人员进入工作区、机械臂卡滞、碰撞或负载可能下落时，应使用现场急停或切断 DC 48 V 供电。收到错误后不要立即重发目标或自动重新使能。

异常的三种交付方式 ​

交付方式典型场景调用方如何处理
接口直接 raise初始化失败、使能前已存在电机故障、参数错误、逆解失败在调用接口的 try/except 中捕获
Arm(..., on_error=callback) 回调运动中的关键硬件故障、连续丢帧、跟踪误差、碰撞停止回调只记录并通知；控制接口返回后由任务层统一处理
限幅、提前返回或日志目标越界、速度/力矩过大、碰撞检测主动停止同时检查返回后的状态、日志和回调，不要只依赖异常

on_error 在控制/反馈路径中同步调用。SDK 会吞掉回调本身抛出的异常，因此回调中不应执行耗时 I/O、等待锁或再次调用机械臂控制接口。推荐在回调中保存错误并设置 threading.Event，等当前控制接口返回后再处理。

SDK 异常类型和诊断字段 ​

除特别说明外，下列类型都继承自 OneroError：

异常诊断字段当前源码中的用途
OneroConnectionErrorchannel、detail创建 CAN 通道或后端时接口不可用
OneroHardwareErrorjoint_index、error_code、description电机故障、使能失败，以及安全监控合成的停机错误
OneroConfigErrordetail型号、构造参数、控制参数、坐标/工具/负载配置不合法
OneroTimeoutErrorjoint_index、missed_frames、detail已公开但当前生产路径没有直接抛出；连续丢帧通过 on_error 交付 OneroHardwareError
OneroSafetyErrorreason、joint_index当前用于笛卡尔轨迹关节跳变和笛卡尔速度奇异点硬阈值
IKConvergenceErrorpos_err、rot_err、iters、pos_tol、rot_tol、q、target_posmovel()、movep()、movec()、servop() 的严格逆解不收敛

IKConvergenceError 当前没有从包根导出，需要这样导入：

python
from onero_sdk.exceptions import IKConvergenceError
1

joint_index 是从 0 开始的源码索引：0 对应 J1，6 对应 J7。-1 表示整机或无法归属某一关节。OneroSafetyError 的文本会显示 joint_index + 1，但字段本身仍是从 0 开始。

公开接口与异常对照 ​

接口或功能直接抛出的主要异常还需要检查的回调或行为
Arm(...)OneroConfigError、OneroConnectionError后续裸 CAN 发送失败不保证全部包装成 SDK 异常
enable()OneroHardwareError；末端执行器可能抛 RuntimeError任一电机使能失败时不会进入可运动状态
movej()、home()OneroError、OneroConfigError目标关节越界会限幅并记录警告；运动中的硬件故障通过 on_error
movel()、movec()OneroError、OneroConfigError，另有 IKConvergenceError、轨迹关节跳变 OneroSafetyError碰撞停止或硬件停机可能提前结束运动而不是从调用点抛出
movep()OneroError、OneroConfigError，另有 IKConvergenceError先严格求解目标位姿，再执行关节空间插补
servoj()OneroError、OneroConfigError位置、速度和力矩由安全后端限幅
servop()上述异常，另有 IKConvergenceError控制循环中仍要处理 on_error
speedj()OneroError、OneroConfigError超过关节速度上限时限幅，不抛速度异常
speedl()上述异常，另有奇异点 OneroSafetyError笛卡尔速度会转换并限幅到安全关节速度
force_mode()OneroError、OneroConfigError主动接触不等于碰撞错误；需自行制定退出条件
freedrive_enable()参数/依赖问题为 OneroConfigError后台示教循环异常会紧急停止，并通过 on_error 交付
CollisionConfig(...)、enable_collision_detection()配置构造可能抛 TypeError、ValueError；未使能时为 OneroError检测结果通过 on_collision、last_collision 和停止时的 on_error 交付
get_state() / arm.state底层异常可能直接上抛高层 ArmState 不含电机错误码和温度，不能用它判定超载；缺帧时可能沿用上次状态
emergency_stop()通常不抛出直接失能并设置急停标志，但不会调用 on_error；后续控制命令会抛 OneroError
stop()OneroError 或安全后端的 OneroHardwareError是受控减速，不等于急停或失能
disable()后端异常撤销保持力矩；机械臂未可靠支撑时不得调用
DualArm.enable()重新抛出单臂异常；并行双侧同时失败时为 OneroError第二条机械臂使能失败时会尝试失能第一条机械臂

参数和调用状态决定具体异常。调用方应从最具体的类型捕获到 OneroError，不能只按接口名假定一种异常。

电机状态与故障码 ​

电机反馈首字节的高 4 位是 MotorError。0x0 和 0x1 是正常状态，其余是电机固件报告的故障：

十六进制枚举含义enable() 前已锁存运行中的当前处理
0x0DISABLED电机失能，正常状态可进入使能流程非故障
0x1ENABLED电机已使能，正常状态可接受为已使能非故障
0x8OVERVOLTAGE过压直接抛 OneroHardwareError，保留 0x8紧急停止并调用 on_error
0x9UNDERVOLTAGE欠压直接抛出，保留 0x9当前不会触发关键故障回调，应结合供电和 CAN 日志排查
0xAOVERCURRENT过流直接抛出，保留 0xA紧急停止并调用 on_error
0xBMOSFET_OVERTEMPMOSFET 过温直接抛出，保留 0xB紧急停止并调用 on_error
0xCCOIL_OVERTEMP线圈过温直接抛出，保留 0xC紧急停止并调用 on_error
0xDCOMM_LOSS电机通信丢失直接抛出，保留 0xD当前记录警告；连续命令反馈丢失由超时监控停机
0xEOVERLOAD电机过载/超载直接抛出，保留 0xE紧急停止并调用 on_error

不能只看运行期回调的 error_code

安全监控触发紧急停止时会新建一个 OneroHardwareError，当前实现把其 error_code 统一设为 0，并把原始故障名写进 description。因此，运行期的超载回调必须同时检查 description 中的 OVERLOAD。0 在这里是 SDK 合成错误码，不应解释为电机的 DISABLED 状态。

安全监控中不会直接抛异常的情况 ​

条件默认阈值或配置当前行为
单帧关节增量过大max_delta_per_step=0.03 rad对命令限幅
关节速度过大max_velocity=6 rad/s，且不超过型号关节限制对命令限幅
目标超出关节位置限制型号 JointSpec 限制限幅并记录警告
力矩命令过大型号力矩限制对命令限幅
连续命令反馈丢失timeout_frames=10紧急停止；on_error 收到 OneroHardwareError(code=0)，不是 OneroTimeoutError
硬跟踪误差1.0 rad 持续 10 帧紧急停止并调用 on_error
软跟踪误差0.5 rad 持续 100 帧紧急停止并调用 on_error
手动 emergency_stop()调用即触发失能并设置急停状态，不调用 on_error

这些默认值来自 SafetyConfig。如果项目覆盖了配置，应在错误日志中一并记录实际配置。

碰撞检测的异常和回调 ​

enable_collision_detection(config, on_collision) 作用于 movej()、movel()、movep()、movec()、speedj() 和 speedl() 的计划运动，不作用于 servoj()、servop() 或 force_mode()。

检测到碰撞后：

  • 只要注册了 on_collision(event)，当前实现检测到事件后都会调用它；event 字段包括 timestamp、channel、joint_index、magnitude、threshold、torques、velocities、joints，并可读取 severity。
  • CollisionResponse.STOP 会执行安全停止；当前实现仍会调用已经注册的碰撞回调。
  • CollisionResponse.CALLBACK 只调用碰撞回调，不自动停止。
  • CollisionResponse.BOTH 同时回调并停止。
  • 选择停止时，运动接口可能提前返回，而不是直接抛出异常；on_error 还会收到 OneroHardwareError(code=0)。
  • SDK 会吞掉 on_collision 回调自身抛出的异常；回调同样应保持短小。
  • arm.last_collision 可读取最近一次碰撞事件。

不要把 OneroSafetyError 当作碰撞检测的通用异常。当前源码中的碰撞交付入口是 on_collision、last_collision 和停止时的 on_error。

末端执行器和底层异常 ​

并非所有可见错误都继承自 OneroError。夹爪、灵巧手和部分底层 CAN/协议接口还可能抛出：

Python 内置异常常见原因
TypeError碰撞响应枚举、回调对象或底层对象类型不合法
ValueError参数范围、帧长度或协议数据不合法
RuntimeError末端执行器未启用、无反馈、状态错误或底层运行失败
NotImplementedError当前末端执行器不支持所调用功能
ImportError缺少可选 CAN 或运动学依赖

因此，硬件应用若使用末端执行器或底层接口，不能只捕获 OneroError。仍应优先捕获具体异常，并在最后单独记录这些内置异常。

推荐处理顺序 ​

  1. 在 Arm 构造函数中注册 on_error，在碰撞检测中注册 on_collision。
  2. 按 OneroConnectionError、OneroHardwareError、IKConvergenceError、OneroSafetyError、OneroConfigError、OneroTimeoutError、OneroError 的顺序捕获。
  3. 回调只复制异常字段、保存现场状态并通知任务层，不在回调里重试、停止或重新使能。
  4. 控制接口返回后检查回调标志。若安全监控已紧急停止，不要再把 stop() 当作恢复动作重复发送。
  5. 保存 joint_index、error_code、description、时间戳、运动目标、实际状态、工具/负载配置和 CAN 日志。
  6. 确认机械和电气原因已经排除后，从低速、小幅动作重新验证。

停止与失能 ​

优先使用 arm.stop(deceleration=...) 中止常规运动。disable() 会撤销电机力矩，只应在机械臂得到可靠支撑后执行。现场紧急情况应优先切断 DC 48 V 供电。

停止、失能与关闭动作对照 ​

场景或用途优先动作是否停止当前运动是否撤销保持力矩是否释放通信资源后续处理
常规任务中止stop()是否否读取状态，确认已停稳
通信或软件异常stop()，必要时切断供电是默认否否保留异常日志并排查 CAN
人员进入区域、即将碰撞等紧急危险现场急停、emergency_stop() 或切断 DC 48 V 供电紧急中止是取决于后续关闭先确保人员和设备安全，再分析原因
已可靠支撑，需要撤销保持力矩disable()是是否确认机械臂不会因失能下落
只释放 SDK/总线资源close()不作为停止流程使用默认否是关闭前单独处理机械臂运动状态
已可靠支撑并结束会话close(disable=True)结束时失能是是确认支撑条件持续有效

程序退出、浏览器关闭和网络断开都不是现场安全动作。应用应把运动中止、失能和资源释放明确写在不同的分支中，并在异常路径中先处理机械臂状态。

stop()、disable()、close() 和紧急停止的含义不同，不能互相替代。

异常后的恢复顺序 ​

异常后不要立即重试，也并非所有异常都需要断电。参数或逆解错误通常只需修正输入；可清除的电机故障在排除原因后可尝试软件恢复：

  1. 确认机械臂已经停稳，人员、工具和工件处于安全状态。
  2. 保存异常、运动目标、关节反馈和 CAN 状态，并排除故障原因。
  3. 可靠支撑机械臂后调用 disable()，失能操作会撤销保持力矩。
  4. 调用 enable()。全部关节均已失能时，SDK 会发送清错指令、尝试重新使能，并复位 SDK 的紧急停止状态；SDK 没有单独的公开清错方法。
  5. 读取状态，先仿真验证，再进行低速、小幅真机复测。不要直接续跑原任务。

现场急停未复位、故障原因不明、温度或供电未恢复、机械结构仍卡滞、CAN 反馈不稳定，或故障再次出现时，应保持停止并断电检查。不要在 on_error 回调中恢复或自动循环重试。

已观察到的问题优先保留的信息
目标没有按预期到达目标值、duration、实际关节角/位姿、负载和速度参数
通信超时或无反馈CAN 接口详情、统计信息、candump 片段和供电状态
笛卡尔方向错误frame、mounting、世界坐标、TCP 和当前位姿
接触或力控异常接触面、selection、wrench、参考坐标系和停止时反馈

保留这些信息可以避免通过反复发送更激进的目标来“试出结果”。
