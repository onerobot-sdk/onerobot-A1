状态、异常与停止 ​

安全处理的优先级是：先让机械臂停止继续运动，再确认机械支撑和供电状态，最后分析异常原因。不要在机械臂仍可能运动时先关闭通信或删除错误日志。

读取状态 ​

python
state = arm.state
print(state.joints)
print(state.velocities)
print(state.torques)

状态读取可用于确认目标是否被接受、运动是否仍在进行以及异常前后的反馈变化。记录状态时建议同时保存时间戳、模型、通道和当前工具/负载配置，便于复现问题。

异常处理 ​

所有 SDK 异常继承自 OneroError。可按需要捕获更具体的异常：

  • OneroConnectionError
  • OneroHardwareError
  • OneroConfigError
  • OneroTimeoutError
  • OneroSafetyError
python
from onero_sdk import OneroError

try:
    arm.movej(target, duration=2.0)
except OneroError as exc:
    arm.stop()
    print(f"机械臂操作失败：{exc}")

异常处理不应只打印错误后继续发送下一个目标。对于连接、超时和安全异常，先停止当前运动；对于配置异常，修正型号、安装方向、TCP 或负载后再重新初始化。

停止与失能 ​

优先使用 arm.stop(deceleration=...) 中止常规运动。disable() 会撤销电机力矩，只应在机械臂得到可靠支撑后执行。现场紧急情况应优先切断 24V 供电。

完整示例：安全停止。

停止动作的选择 ​

场景优先动作后续处理
常规任务中止arm.stop()读取状态，确认已停稳
通信或软件异常arm.stop()，必要时切断供电保留异常日志并排查 CAN
机械臂即将碰撞或人员进入区域现场急停或切断 24V先确保人员安全，再分析原因
已可靠支撑、需要撤销保持力矩disable()确认不会因失能下落

stop()、disable()、close() 和紧急停止的含义不同，不能互相替代。

异常后的恢复顺序 ​

异常发生后，不应立即重新运行同一段运动代码。建议按以下顺序恢复：

  1. 先确认机械臂是否已经停止，以及人员、工具和工件是否安全。
  2. 保存异常信息、时间戳、目标、关节反馈和 CAN 状态。
  3. 判断问题属于通信、配置、目标可达性、负载/TCP 或外部控制器中的哪一类。
  4. 修正配置后，先执行只读状态检查和仿真验证，再进行小幅、低速真机复测。
已观察到的问题优先保留的信息
目标没有按预期到达目标值、duration、实际关节角/位姿、负载和速度参数
通信超时或无反馈CAN 接口详情、统计信息、candump 片段和供电状态
笛卡尔方向错误frame、mounting、世界坐标、TCP 和当前位姿
接触或力控异常接触面、selection、wrench、参考坐标系和停止时反馈

保留这些信息可以避免通过反复发送更激进的目标来“试出结果”。
